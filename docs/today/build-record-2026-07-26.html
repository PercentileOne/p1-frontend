State at session start — what was broken

Every CI deploy had been silently failing since 24 July because the SWA deployment token secret was missing from GitHub. The live site was running the old OpenAI-based bundle. All API calls from the browser were blocked by CORS. The CV preview showed HEURISTIC instead of AI data. Mike's intro was gone. James spoke twice.

🔒

CI deploy dead since July 24

broken

AZURE_STATIC_WEB_APPS_API_TOKEN_EXPLAIN_GLOBAL was missing from GitHub repo secrets. Every push to main silently failed with "deployment_token was not provided." The live site was frozen on the old bundle.

🚫

CORS blocking all API calls

broken

api.explain.global (Azure Function App) only whitelisted portal.azure.com. Every browser request from recruiter.explain.global — including GET /health — returned "Failed to fetch."

🔗

Wrong API URL baked into bundle

broken

VITE_EXPLAIN_API_URL was never set in the CI workflow. Vite fell back to explain-api.azurewebsites.net — a URL the browser cannot reach. All fetch calls failed before CORS was even checked.

🤖

Wrong Anthropic model name

broken

AnthropicExplainAIClient referenced claude-sonnet-5-20251101 which does not exist. Every call to /cv/parse and /session/prepare returned 500 from the Function App.

💾

Cosmos DB not provisioned

broken

The explain database didn't exist in the Cosmos account. CVParserService called the AI successfully but then crashed trying to write to CVProfiles, returning 500 instead of the parsed data.

🎬

D-ID returning 500

broken

The SWA API function /api/did-talk used fetch() — not available in all Node runtimes. Also, the API folder wasn't included in the swa deploy dist command, so the function was never updated.

🔊

Mike missing · James speaking twice

broken

When D-ID failed, startInterview() had a race condition: speak(mikeScript, 'technical', () => {}) fired with an empty callback (no cancel, no chain), and then the catch block immediately called beginInterviewIntro(). Sarah and James-as-Mike spoke simultaneously. James then spoke his own intro on top — appearing to speak twice. In the D-ID success path, speak() also fired unnecessarily alongside the video.

Fixes shipped — in order
1 · SWA deployment secret added
Francis added AZURE_STATIC_WEB_APPS_API_TOKEN_EXPLAIN_GLOBAL to GitHub repo secrets. CI deploys restored. Direct swa deploy used immediately to push live without waiting for CI.
2 · CORS opened for all explain.global origins
Added recruiter.explain.global, client.explain.global, and candidate.explain.global to the Function App CORS allowlist via az functionapp cors add. Verified: GET /health from the browser returns 200 with correct Access-Control-Allow-Origin.
3 · VITE_EXPLAIN_API_URL added to CI workflow
Added VITE_EXPLAIN_API_URL: https://api.explain.global to the Build step env vars in .github/workflows/deploy-swa.yml. Rebuilt locally with the env var — new bundle hash index-fdxmY5Cj.js — confirmed api.explain.global appears once, explain-api.azurewebsites.net zero times. Deployed directly.
4 · Anthropic model corrected
AnthropicExplainAIClient: changed Model constant from claude-sonnet-5-20251101 (non-existent) to claude-sonnet-4-5. Confirmed via direct Anthropic API call — responds correctly with "model":"claude-sonnet-4-5-20250929".
5 · Cosmos write made non-fatal
CVParserService.ParseAsync: wrapped the Cosmos CreateAsync call in try/catch. If the write fails (database not provisioned), logs a warning and returns the AI result anyway. CV parse now works end-to-end without requiring Cosmos.
6 · Achievement prompt criteria relaxed
The AI CV prompt had overly strict rules ("MUST satisfy BOTH: number/£/% AND measurable outcome"). Changed to include: named system delivered, team led, promotion, major project completion. Achievements now surface correctly for real CVs.
7 · D-ID API function rewritten
Replaced fetch() with Node's built-in https module in /api/did-talk/index.js — works in all Node runtime versions. Redeployed including the --api-location api flag so the function is actually shipped with the SWA bundle.
8 · Mike intro & interview start sequence fixed
D-ID success path: removed the redundant speak() call — the video carries its own audio. D-ID fail path: voice-only Mike now chains correctly into beginInterviewIntro() via callback, with cancelSpeakRef properly managed. James no longer speaks twice.
