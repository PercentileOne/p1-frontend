Candidate Profile Foundation

Francis's direction: everything the platform is building toward — Candidate Search, team-fit matching, founder-matching, org discovery — depends on the profile underneath it being right first. This is that plan.

🔍
Found while scoping this

Most of the rich profile UI already exists — ProfilePage.tsx is a fully designed "Profile Page 2.0" with Overview, Story, Posts, Achievements, Walls, Groups, Awards, Interests, and Video tabs. It's just running entirely on mock data (profileData.ts's OWN_PROFILE), never connected to the real backend. This isn't a from-scratch build — it's finishing something already half-designed.

⚠️
The one hard "no" in this plan

Letting candidates enter raw HTML for their profile is a real security hole — anyone could embed a script that runs for every recruiter who views their page. The fix that still gets "better than LinkedIn's About section" (real bold, headings, lists) is a proper rich-text editor that stores structured content and renders it safely — never raw HTML from a user, ever.

01 The four phases

In the order Francis's own read of the direction implies — each phase only makes sense once the one before it has real data behind it.

1
Next up

Profile Foundation

Expand the real schema, wire the existing rich UI to real data instead of mocks, add photo + banner upload, replace the plain-string Bio with a safe rich-text editor.

2
After Phase 1 ships

Likes & social signals

A lightweight "who liked whom" graph, layered onto profiles that already exist — feeds the recommendation logic Phase 4 needs. Doesn't block anything before it.

3
Independent track

Media enhancement

Photo/video filtering and quality enhancement. A genuinely separate capability (a real media-processing pipeline) — can be scoped and built in parallel with Phases 1-2 rather than waiting on them.

4
The actual goal

Candidate Search + Org pages + Social

The page everything else has been building toward — searchable by hobbies/interests/projects for team-fit, candidate-to-candidate discovery, groups, founder-matching (YC-style), organisation search, organisation home pages. Only as good as the data Phase 1 puts in the ground.

03 Open questions — worth deciding before building

  • Which portals get the rich profile? Candidates clearly do — do Recruiters and Employers get the same depth, or a simpler version, given their profiles serve a different purpose (representing a company, not "who am I")?
  • Interests vs. Hobbies vs. Likes — one field or three? They're closely related but Francis named them separately. Worth deciding if they're genuinely distinct search facets or the same underlying list styled differently in the UI.
  • Does the existing mock social UI (Walls, Groups, Posts, Achievements) get revived as-is, or redesigned? It's real, existing design work — worth a deliberate call rather than defaulting to either "keep everything" or "start over."
  • Moderation. Once bios, projects, and hobbies are free-text and publicly visible to recruiters/other candidates, is any content moderation needed before Phase 4 makes profiles broadly discoverable?
