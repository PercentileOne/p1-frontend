Azure SQL · Identity & Auth

Auth Architecture
Explain.global

Full Azure SQL schema and behavioural spec for identity, authentication, session management, role-based access, and locale resolution across all Explain portals. No transactional auth data lives in Cosmos DB.

🔒
Guardrail — Cosmos DB is off-limits for auth
All identity, session, role, permission, and audit data lives in Azure SQL. Cosmos DB is reserved for interview transcripts, lesson content, careers data, and non-transactional document blobs. This boundary is permanent and non-negotiable for YC-level data integrity and audit compliance.

Core Principles

🏛️
Single identity, multi-portal
One Users row grants access to Candidate, Recruiter, Admin, and future portals — controlled by UserRoles, not separate user tables.
🌍
Multi-language by design
PreferredLanguageCode and PreferredCountryCode live on Users. RegionContext reads from the session first, browser second.
🔐
SSO-ready from day one
UserLogins decouples identity providers from local credentials. Add LinkedIn, Google, or Microsoft OAuth without touching the user table.
📋
Full audit trail
Every login attempt — success or failure — is written to UserLoginAttempts. Lockout logic, IP rate-limiting, and forensics are all SQL-native.

How the app uses it

On every authenticated request, usp_ValidateSession returns PreferredLanguageCode and PreferredCountryCode alongside the session. RegionContext reads these first; only falls back to navigator.language if the user has no preference set. The IsRTL flag is read directly from the session payload to set document.documentElement.dir.

Flow: Registration

1
Validate input & check uniqueness
Application layer normalises email (UPPER(TRIM(email))), validates format, hashes password with Argon2id. Query Users to confirm email not already registered for this tenant.
2
Call usp_RegisterUser (single transaction)
One stored procedure, one transaction. Writes in order:
Users UserProfiles UserRoles (Candidate) UserSessions UserLoginAttempts UserTwoFactor
3
Issue email verification token
Application generates a cryptographically random token, hashes it, writes to EmailVerificationTokens. Raw token is emailed to the user.
EmailVerificationTokens
4
Return session token to client
The raw session token (from step 2) is set as an httpOnly cookie. The user is logged in immediately — email verification is enforced at feature level, not login level.

Flow: Login

1
Fetch user record
Call usp_ValidateLogin — returns user row including PasswordHash, IsLocked, LockedUntil, TwoFactorEnabled.
UsersUserTwoFactor
2
Check lockout
If IsLocked = 1 and LockedUntil > NOW, reject immediately. Record the attempt with FailureReason = 'account_locked'.
3
Verify password (application layer)
Argon2id verify in application code — never in SQL. Result passed to step 4.
4
Call usp_RecordLoginResult
On success: resets FailedLoginCount, creates UserSessions row, records attempt. On failure: increments counter, locks after 5 failures.
UsersUserSessionsUserLoginAttempts
5
2FA gate (if enabled)
If TwoFactorEnabled = 1, session is created in a pending state. TOTP/SMS code must be verified before full access is granted. See 2FA flow below.

Flow: Session Validation

1
Extract & hash bearer token
Application middleware reads the httpOnly cookie or Authorization: Bearer header, SHA-256 hashes the raw token.
2
Call usp_ValidateSession
Returns full user + profile + locale in one query. Returns empty if token is expired, revoked, or user is inactive. Also updates LastActivityAt.
UserSessionsUsersUserProfiles
3
Inject into request context
UserId, TenantId, Portal, permissions, and locale are attached to the request context. No further SQL calls needed for auth on that request.

Flow: Authorisation

1
On session create — resolve permissions
Call usp_GetUserPermissions once. Returns all Code values the user holds across all their roles.
UserRolesRolePermissionsPermissions
2
Cache in session / JWT
Permission codes array is stored in the session token payload (or Redis). No SQL hit per request. Cache is invalidated when roles change or session is revoked.
3
Middleware permission check
Each API route declares required permissions. Middleware checks permissions.includes('CAN_BOOK_INTERVIEW') — no SQL. 403 if missing.

Flow: Two-Factor Auth

1
Enable 2FA
App generates TOTP secret via otplib, encrypts with Azure Key Vault key, writes to UserTwoFactor. User scans QR code and confirms with first code.
UserTwoFactor
2
Login gate
After password verified, if IsEnabled = 1: issue a short-lived pre-auth token (5 min), return {"requires2FA": true}. Full session not yet created.
3
Verify TOTP / backup code
App decrypts SecretKey, verifies code via otplib. On success: create full session, update LastUsedAt in UserTwoFactor.
UserTwoFactorUserSessions

Stored Procedures

usp_RegisterUser
Single transaction: creates Users, UserProfiles, UserRoles (Candidate), UserSessions, UserLoginAttempts, UserTwoFactor. Returns new UserId and SessionId.
usp_ValidateLogin
Fetches user row + 2FA config for password verification in application code. Does not record the attempt — that happens in usp_RecordLoginResult.
usp_RecordLoginResult
Records attempt, creates session on success, increments failure counter and applies lockout on failure. Always called after application-layer password verification.
usp_ValidateSession
Called on every authenticated API request. Returns user + profile + locale. Updates LastActivityAt. Returns empty set if session is invalid, expired, or revoked.
usp_GetUserPermissions
Returns all permission Code values for a user via UserRoles → RolePermissions → Permissions join. Called once at session create; result cached for session lifetime.
usp_RevokeSession
Soft-revokes a single session by SessionId. Used on explicit logout.
usp_RevokeAllUserSessions
Revokes all sessions for a user — used on password change, account suspension, or admin action. Accepts an optional ExceptSessionId to keep current session alive.
usp_PurgeExpiredSessions
Maintenance proc — run daily via SQL Agent. Deletes sessions expired more than @RetentionDays (default 30) ago.
