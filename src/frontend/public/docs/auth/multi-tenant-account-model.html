Multi-Tenant Account Model

How Agencies and Employers get an account on InterviewMe — a login flow, a data model, and the admin screens your team uses to run it, all built on RBAC and org tables that already exist in the database.

Scope — Recruiter & Employer accounts only
Candidate accounts — unchanged, self-serve
Status — three open decisions below
01

The shape of it

One product, two very different ways in. A candidate is a person; an Agency or Employer is an organisation — and an organisation doesn't sign itself up.

Self-serve

Candidate

Anyone can register in thirty seconds. No approval, no sales conversation — the product sells itself.

  1. Visits the register page
  2. Fills in name, email, password
  3. Account is live immediately
Sales-assisted

Agency / Employer

Nobody can claim to be "Barclays" by typing it in a box. An organisation only exists because someone on your team put it there.

  1. Calls or emails you
  2. Your team creates the org in Admin
  3. Your team invites their first user by email

04

Billing: seat fee + usage

What you described — a flat monthly fee plus a per-prep charge on top — is a completely standard SaaS structure. It has a name: a subscription with metered usage. Twilio, SendGrid and Zendesk all bill this exact way, and Stripe has a built-in "metered billing" mode built for precisely this.

Vallum Associates

AUG 2026
Worked example, illustrative figures
Seat fee — Agency plan£299.00
Interview preps sent — 340 × £1.00£340.00
Total this month£639.00

The seat fee is billed upfront, monthly, regardless of usage — it's what keeps the org's login working.

The £1/prep charge is metered — tallied through the month, billed in arrears once the month closes.

For now: track prep counts per organisation and surface them in Admin (§5) as a running total. That alone tells you what to invoice by hand.

Later: once volume justifies it, feed that same count into Stripe's metered billing API and invoicing becomes automatic.

05

The admin screens

Four screens, each doing one job. All gated behind the existing CAN_VIEW_ADMIN_PORTAL permission.

Screen 1

Organisations

The master list — every Agency and Employer, and the entry point for creating a new one after a sales call.

  • Name, type, status, seat count
  • "+ New Organisation" form
  • Search / filter by type
Screen 2

Organisation detail

Everything about one org — this is where the billing worked example above actually lives.

  • Seat fee, prep unit price, running total
  • Preps sent this billing period
  • Member list + pending invites
Screen 3

Invite a member

How a new recruiter or employer contact actually gets in — see the open question in §6 on the approval step.

  • Email + role (Recruiter / Employer)
  • Pending / accepted / revoked status
  • Resend invite
Screen 4

Login history

The data's already being written on every login attempt — this screen just puts a face on it.

  • Who signed in, when, from where
  • Failed attempts flagged
  • Filterable by organisation
06

Where we landed

From this conversation — two settled, one still worth a moment's thought.

Seats = monthly access fee

A flat recurring charge for the org's access, separate from usage. Confirmed above as the "seat fee" line.

Settled

Org dropdown stays a short static list

No search needed while the list is short — revisit only once it genuinely grows long.

Settled

Invite vs. self-request-and-approve

You leaned toward admin-invites-each-person, with maybe a lightweight self-request option later. Recommendation: build the invite flow first — it's simpler and covers the real case — and add a "request to join" path only if agencies actually ask for it.

Open
07

Suggested build order

Phase 1

Wire up what already exists

Add orgId to the JWT, connect Organisations/OrganisationMembers to real endpoints, add the two new billing columns.

Phase 2

Admin screens 1–3

Organisation list, org detail, and the invite flow — everything your team needs to onboard an agency by hand.

Phase 3

Login flow

The org dropdown on Login/Register, gated to Recruiter/Employer roles.

Phase 4

Usage & login history

Tally interview preps per org for the billing view; surface LoginHistory as Admin Screen 4.

Phase 5

Stripe metering

Only once real invoices are being sent by hand and volume justifies automating it.
